# OCR 任务由 Host 分步驱动，工作进程只做短请求

OCR 是分钟级任务，服务端提供页进度但没有取消接口；插件的工作进程串行处理请求，单次调用 600 秒超时会把整个进程停掉。决定由 Host 依次发起提交、轮询、取结果三个短请求，每次请求都在工作进程里立即返回，任务状态落在磁盘上，界面照常查询。取消只停止本地轮询并把任务标记为已取消，不承诺撤回云端任务。

## Considered Options

- 在工作进程里阻塞等待：实现最短，但转换期间查询会被排队，看不到进度，超时还会杀掉工作进程。
- 工作进程内开后台线程：能保留单一数据所有者，但锁、状态与退出顺序都要重做，复杂度高于收益。

## Consequences

- 任务状态机横跨 Host 与 Python，两边都要认同一份 `job.json`。
- Host 或进程重启会留下停在运行中的任务，与现有转换任务的处理一致。
